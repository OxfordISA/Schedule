# ISA Conference Schedule — Reusable Template

## Overview

This is a reusable template for the ISA conference schedule. It contains everything needed to go from raw submissions to a published schedule (PDF + web app). To use for a new conference, update the data files and `code/config.R`, then run the pipeline.

## Quick Start for a New Conference

1. Export raw submissions from the conference management system → `data/submissions_raw.csv`
2. Edit `code/config.R` with new conference details (dates, venue, tracks, IDs, constraints)
3. Run the pipeline in order (see Workflow below)

## Workflow

Run these scripts in order:

```
Rscript code/0clean.R               # Raw submissions → data/submissions.csv
Rscript code/0b_export_for_chairs.R  # Generate draft CSVs for track chairs → data/sessions/draft/
# --- Track chairs organize papers into sessions, save to data/sessions/ ---
Rscript code/1generate_session_ids.R # Build data/session-ids.csv from data/sessions/ CSVs
Rscript code/2assign_slots.R         # Assign sessions to time slots → data/schedule.csv
Rscript code/3exclude.R              # Remove excluded IDs
Rscript code/4generate_json.R        # Build JSON for the web app → json/*.json
quarto render schedule.qmd           # Render the full program PDF
Rscript code/5verify.R               # Verify all constraints
```

## File Structure

```
code/
  config.R                    # ALL conference-specific settings (dates, IDs, tracks, constraints)
  setup.R                     # Loads libraries
  0clean.R                    # Raw submissions → submissions.csv
  0b_export_for_chairs.R      # Generate draft CSVs for track chairs to organize
  1generate_session_ids.R     # session-ids.csv from data/sessions/ CSVs
  2assign_slots.R             # Assigns sessions to time slots → schedule.csv
  3exclude.R                  # Removes excluded IDs
  4generate_json.R            # Generates all JSON files for web app
  5verify.R                   # Test suite for scheduling constraints
  generate_badges.R           # Generates badges.pdf

data/
  submissions_raw.csv         # Raw export from conference system
  submissions.csv             # Cleaned submissions (output of 0clean.R)
  sessions/                   # Per-track CSVs: id, session_id, session_name, paper_order
    draft/                    # Generated by 0b — track chairs organize these
  self-sessions.csv           # Papers within self-organized panels
  session-ids.csv             # Paper → session mapping (output of step 1)
  session-slots.csv           # Available time slots and rooms
  schedule.csv                # Full schedule with slots/rooms (output of step 2)
  panels.csv                  # Special sessions and plenaries
  overview.csv                # Full program overview (breaks, meals, events, excursions)
  excursion-program.csv       # Excursion detailed program
  pdw-registered.csv          # PDW registrants (cannot present in PDW-overlap slots)
  bios.csv, bio-panels.csv    # Speaker bios for special sessions
  awards.csv                  # Award winners and runners-up
  committee.csv               # ISA leadership/committee
  registrants.csv, guests.csv # For badge generation

css/style.css                 # Web app styles (extracted from index.html)
js/app.js                     # Web app logic (extracted from index.html)
json/                         # JSON data files for web app (generated by step 4)
index.html                    # Web app shell (served by GitHub Pages)
schedule.qmd                  # Quarto source for the PDF program
images/                       # Logo, photos, sponsor logos, speaker bios
```

## Paper Ordering

Paper presentation order within sessions is controlled by the `paper_order` column:
- In `data/sessions/*.csv`: track chairs set `paper_order` (1, 2, 3, ...) for each paper
- In `data/self-sessions.csv`: `paper_order` column controls order within each panel
- This `paper_order` flows through `session-ids.csv` → `schedule.csv` → both the PDF and web app

This is explicit and robust — no reliance on row position.

## Configuration (`code/config.R`)

Everything conference-specific lives here:
- Conference name, dates, venue, timezone
- Track definitions (name, short code, color)
- Submission IDs: rejected, withdrawn, dissertations, panels, self-organized
- Scheduling constraints: date restrictions, date exclusions, slot restrictions
- PDW overlap slots
- Award name mappings
- Recategorization overrides
- Random seed for slot assignment

## Session Constraints

- Each paper session must have 3-4 papers (verified by 5verify.R)
- No author can appear in two sessions at the same time slot
- PDW registrants cannot present during PDW-overlap slots
- Date/slot restrictions and exclusions are honored

## Workflow Rules

- **Never run R scripts or render `.qmd` files.** The user always does this.
- After making edits, ask the user to run the relevant script.
- **Never run `git` commands.** The user handles commits.
